# Protocols：输入时效性、协作边界与报告规则

> 由 `SKILL.md` 引用。在核对输入、判断能否验收、记录「有条件通过」或维护报告时读取。

## 验收开始前的时效性检查

进入综合检查链之前必须完成：

- 确认最终验收使用的需求版本（与开发就绪任务报告中的版本一致，或明确记录变化）。
- 确认代码差异、Testing 报告、代码 Review 结论对应同一代码版本；发现引用的 Commit 不一致时，先确认是否需要重新提供对应版本的证据，而不是直接合并不同版本的结论。
- 检查开发就绪项目基线（`docs/development-readiness/<timestamp>-baseline.md`）之后是否发生与本任务相关的变化。
- 检查开发过程中用户或业务方批准的范围变化是否已经写入任务契约；未写入的口头变化视为未确认，需要向用户核实。

发生实质变化时，不能只输出依赖旧文件才能读懂的增量说明；应在报告中给出完整的新版本结论，并简要说明相对上一版本的变化。

## 输入缺失或形式不统一的处理

- **Testing 报告缺失**：标记为无法验收所需的关键输入之一；风险明显较低且用户明确接受时，可以退到「有条件通过」并记录该条件，但不能自行判「通过」。
- **代码 Review 结论缺失或形式不统一**（PR 评论 / 检查清单 / 口头小结 / 完全没有）：记为证据缺口，按任务风险决定是否阻断；高风险任务（涉及权限、数据、支付、跨服务）缺少任何代码质量核对时应阻断，低风险任务可以在「有条件通过」中记录该缺口。
- **原始需求或开发就绪材料缺失**：无法判断需求一致性和职责覆盖时，标记「无法验收」，不能只依赖代码差异自行猜测需求。

## 与代码 Review 的协作边界

- 只保留两个角色：既有代码 Review 能力判断代码本身是否正确、可靠、可维护并符合项目规范；本 Skill 综合需求、范围、全局影响、测试和 Review 证据做最终判断。
- 不为需求覆盖、越界、功能证据和回归风险分别创建固定子 Agent；它们共享大量上下文且需要连续判断，拆分只会导致重复调查。
- 特殊安全、数据库迁移、性能或无障碍风险确有必要时，可以按需调用专项能力核实某一点，但不作为固定流程，且不能让专项结论替代本 Skill 的综合判断。

## 「有条件通过」的记录要求

写「有条件通过」时必须同时记录：

- 条件内容（具体、可核对，不是模糊描述）。
- 接受者（角色名，例如「业务 Owner」「模块 Owner」，不编造人名）及接受时间。
- 是否有后续任务、Issue 或提醒机制跟踪剩余风险；没有跟踪机制时要在报告中显式提示这一点。

缺少接受者或条件内容时不能写「有条件通过」，应退回「需要业务或用户决策」。

## 知识回流

- 在报告的「知识回流」小节列出建议更新到项目基线的内容（新约定、废弃路径、修正的过期文档），不直接修改 `docs/development-readiness/**` 下的文件——那些文件的更新节奏由 development-readiness 自己的会话维护。
- 用户或团队可以把这些建议带入下一次 development-readiness 会话进行合并。

## 报告与会话交接

会话启动时用 UTC 生成兼容 Windows 的时间戳 `YYYY-MM-DDTHH-mm-ssZ`：

- `docs/scenario-acceptance/tasks/<timestamp>-<task-id-or-slug>.md`

`<task-id-or-slug>` 复用上游（开发就绪、测试）确定的任务 slug。同一会话持续更新该文件；需求或代码发生实质变化后的重新验收创建新时间戳版本，保留旧版本用于追溯。

使用 `report-template.md` 的固定标题与信息位置；无内容的可选小节可以省略。已经在上游报告中确认的事实只引用路径，不重复抄写全文。

```markdown
- 验收结论：通过 / 有条件通过 / 需要修复 / 需求待确认 / 无法验收
- 判断理由：
- 阻塞验收的问题：
- 需要修复但不阻塞的问题：
- 需要业务或用户决策的问题：
- 已验证通过的验收项：
- 无法验证的项目：
- 已被明确接受的剩余风险（如为有条件通过，含接受者与跟踪方式）：
- 知识回流建议：
- 报告：`docs/scenario-acceptance/tasks/<timestamp>-<task-id-or-slug>.md`

下一步：
- 通过：可以交付。
- 有条件通过：按记录的条件交付，跟踪剩余风险。
- 需要修复：退回开发，修复后重新测试与验收。
- 需求待确认：先获得业务或用户决策，再判断是否需要重新开发。
- 无法验收：先补齐缺失的关键资料或证据。
```
