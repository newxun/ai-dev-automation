# Memory：云效身份/上下文缓存

## 目的

组织 ID、当前用户 ID、常用项目 ID、字段约定（例如"参与者"具体指哪个字段）这类信息，在一个人/一个团队的使用周期里几乎不变，但云效 MCP 本身没有"默认组织/项目"这类服务端配置，每次都靠 Agent 现查会浪费掉 2~3 次工具调用。这份 memory 把这些静态事实缓存成本地文件，读写协议见下方，也同步写在 `../SKILL.md` 的「身份与上下文解析」里。

## 文件

- `context.json`：真实缓存文件，**不提交到 git**（已在仓库根 `.gitignore` 中排除）。里面会写入你所在组织的真实 organizationId / projectId / userId，属于环境相关的个人配置，不应该跟着这个公共 Artifact 仓库分发给别人。
- `context.example.json`：结构模板，提交到 git，说明每个字段的含义。第一次使用时 Agent 会照这个结构新建 `context.json`，不需要手动复制。

## 读写协议

1. 开始解析组织/项目/用户信息前，先读 `context.json` 是否存在且相关字段非空。存在就直接复用，不重新调用 `get_current_organization_info` / `get_user_organizations` / `get_current_user` / `search_projects`。
2. 文件不存在，或缓存的 ID 在实际调用中失败（返回 404/403，说明组织/项目已变化）时，才现查一次，并把新解析出的值写回（或按 `context.example.json` 结构新建）`context.json`，同时刷新 `updatedAt`。
3. 这一步写入不需要额外找用户确认——纯本地缓存文件，不发送给任何人、不提交到 git，写错了删掉重新生成即可，和"协作类/结构类/高风险类"写操作不是一回事。
4. 用户在当前对话里明确给出的 ID，优先级高于缓存，直接用，不用旧缓存覆盖。

## 何时应该手动清空重建

- 换了组织，或者常用项目发生了变化。
- 云效那边的字段配置调整了（比如"验收标准"换了自定义字段、"参与者"具体指哪个字段变了）。
- 怀疑缓存内容已经过期（`updatedAt` 太久远，或者最近多次调用都要现查修正）。

直接删除或清空 `context.json` 对应字段即可，Agent 下次会自动重新解析并写回，不需要额外的维护脚本。
