# Doc Review Views

把散落在 docs/ 各处、需要人工逐条核对的长文档统一渲染成好读的 HTML，并汇成一个目录索引页。

定位：**md 是归档面（Agent 侧），HTML 是人审面（人类侧）**——md 保持档案密度的完整证据（问题点 × 严重度 × 证据标签 × 处置口径，供 Agent 与留档消费）；HTML 服务人审「核对 + 做决定」的工作流（筛选、搜索、折叠、待决队列），而不只是把线性长文「排版更好看」。人审体验的演进一律走 HTML 侧，不反向要求 md 为本 skill 改格式。

## 核心原则

- **md 是唯一源**。本 skill 只读 md、只写派生物（统一输出到 `docs/review-views/` 单一目录：目录页 `index.html` + 各文档视图 `.html`），绝不修改 md。
- **幂等**。重复执行只是刷新派生物；md 更新后重跑即可，删掉 HTML 也随时可重建。
- HTML 必须自包含单文件：file:// 双击可开、无外部依赖、离线可用、深色模式自适应。
- **人审面演进只在 HTML 侧**：待决事项抽取、队列筛选等审阅决策面能力由视图层从现有 md 内容（标签 + 措辞）识别；需要 md 侧加结构化钩子（选项确认、角色切片等）的方向是中期演进，见配套 README 的 Roadmap，勿擅自给上游文档族加输出要求。

## 用法

```bash
node <本skill目录>/assets/build.mjs <项目根目录>
```

产出：

1. `docs/review-views/` 下为每份被收录的 md 生成同名 `.html` 审阅视图（文档站常规三栏布局：**左栏「全部文档」菜单**，可不回目录页直接切到目录内任意其他文档，另有「← 审阅目录」返回链接；**右栏「本页大纲」页内导航**，带各节问题计数、滚动联动高亮。工具栏提供**待决队列**（只看待人拍板的条目）、按严重度/证据冲突筛选、搜索高亮、问题卡片折叠、证据标签着色徽章、打印时自动展开、文末可展开 md 源码）。
2. `docs/review-views/index.html` 目录页，与所有视图**同目录**：按「项目级/迭代级文档」（核对报告、就绪基线）与「需求号」（从文件名提取，如 HWTQ-2929）分组，条目带类型徽章、日期、问题计数、待决计数、md 源文件链接；打开目录页即可在目录内任意切换各视图。重跑会先清空该目录下旧 `*.html` 再重建——该目录是派生物专区，勿手放其他文件。
3. 脚本逐行打印生成清单与计数；**把清单汇报给用户，并给出目录页绝对路径**。

未找到任何已知文档族时脚本报错退出：此时先与用户确认文档路径，确认后由人决定是否扩 `FAMILIES`，不要擅自放宽扫描范围。

## 文档族规则（扫描白名单）

| 目录 | 文件名规则 | 类型 |
| --- | --- | --- |
| `docs/requirement-consistency-check/` | 直接子文件 `*.md`（排除 README.md） | 一致性核对 |
| `docs/development-readiness/` | 直接子文件 `*-baseline.md` | 就绪基线 |
| `docs/development-readiness/tasks/` | 直接子文件 `*.md`（raw/ 子目录天然排除） | 任务就绪报告 |
| `docs/scenario-acceptance/` | 直接子文件 `*.md`（排除 README.md） | 场景验收 |
| `docs/scenario-acceptance/tasks/` | 直接子文件 `*.md` | 场景验收报告 |

只取各目录**直接子文件**，不递归；`README.md` 与 `raw/`（用户原始材料）一律不转。新增文档族前先与用户确认目录与命名规律，再改 `build.mjs` 的 `FAMILIES` 与本表。

## 计数口径（目录页卡片与视图 pill 同源）

`build.mjs` 的 `analyze()` 与阅读视图模板 JS 的 pill 计数使用**同一套识别规则**：

- **条目**：严重度标题（含 高优先/中低/轻微）下的问题卡片（`**A1. …**` + 列表）、表格行（2 列元信息表除外）、顶层列表项各算一个。
- **证据冲突**：条目标签含 `` `[证据冲突]` `` 且不含「消解」。
- **待决**：条目的标签或正文措辞命中 `待确认|未确认|未验证|需要澄清|需澄清|待澄清`（标签与纯文本合并检索；`[留开发]` 不算——处置已定，不欠人拍板）。问题卡片按标题行判定，与冲突计数同一基准。

文档族没有的档位（如就绪报告无严重度章节）pill 自动隐藏，属预期。

若目录页计数与页面内 pill 数字不一致，视为 bug：修 `analyze()` 对齐模板 JS，不要各改各的。

## 模板维护（assets/template.html）

- 占位符：`{{TITLE}}`（`<title>`）、`{{BRAND}}`（左栏标题）、`{{DOCLIST_HTML}}`（build.mjs 注入的左栏「全部文档」菜单，与目录页同分组、当前篇高亮）、`{{MARKDOWN_JSON}}`（md 内容以 JSON 字符串注入；`</` 与 `<!--` 已由 build.mjs 转义，防提前闭合 script）。
- 布局：左栏 `#sidebar`（brand + 全部文档菜单）、右栏 `#tocbar`（本页大纲）；≤1280px 隐藏右栏、≤920px 隐藏左栏，打印时两栏都隐藏。
- 侧栏「← 审阅目录」链接硬编码 `href="index.html"`，依赖「视图与目录页同目录」的输出布局（`docs/review-views/`）；若改输出位置须同步改此链接。
- 代码内联占位哨兵是 ``/`` **转义写法**（inline() 里成对出现）：不要改成裸控制字符（编辑器不可见、极易误删），也不要动这对逻辑。
- 改模板后必须在样例文档上重验（chrome-devtools MCP 打开生成的页面断言），最小集：
  1. 一致性核对样例：pill 计数 = build.mjs 打印的计数；点「证据冲突」后可见条目数 = pill 数；点「待决」后可见条目数 = pill 数，且每条含 待确认/未确认/未验证/需澄清 类措辞；搜索关键词出 `<mark>` 高亮；
  2. 就绪基线/任务报告样例：无严重度章节时仅显示「全部」pill（条目登记只发生在严重度章节内，待决队列不覆盖这类文档，属预期）；侧栏大纲可点、滚动联动；console 无报错；
  3. `查看 Markdown 源码` 折叠块内容非空。

## 边界

- 不生成、不修改 md 本身——md 的产出契约属于各生成侧 skill（requirement-consistency-check、development-readiness、scenario-acceptance），本 skill 只消费。
- 待决/冲突等审阅语义是**规则识别**（见计数口径），不保证穷尽；识别规则变更须同步改 `analyze()` 与模板 JS 并在样例上重验。
- 不引入构建工具链或外部依赖：模板是原生 JS，build.mjs 只用 node 内置模块。
- 产物是本地审阅视图，不发布、不上传。
