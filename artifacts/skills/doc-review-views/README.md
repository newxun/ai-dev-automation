# Doc Review Views

## Problem

本仓库主线 Skill（requirement-consistency-check、development-readiness、scenario-acceptance）产出的核对报告 / 就绪基线 / 任务就绪报告 / 验收报告，本质是「问题点 × 严重度 × 证据标签 × 处置口径」的结构化数据，却以线性 markdown 铺开：人工逐条审阅费劲，审阅时想只看「欠人拍板的条目」也无从下手。

首轮 HTML 化曾停留在「同密度证据档案换皮」——更好读，但仍不是人审决策面（见 skill-bug log 2026-09-04T06-33-22Z 条目）：审阅者要的是决策队列，不只是阅读器。

## Goal

把这批「需人工核对」的 markdown 文档族批量渲染成自包含 HTML **审阅视图** + 一个目录索引页，并明确两层分工：

- **md 是归档面（Agent 侧）**：保持档案密度的完整证据，供 Agent 与留档消费，是唯一源。
- **HTML 是人审面（人类侧）**：服务人审「核对 + 做决定」的工作流——待决事项队列、按严重度/证据冲突筛选、搜索高亮、问题卡片折叠、大纲导航，全部由现有 md 内容规则识别而来，**不反向要求 md 改格式**。

## Use Cases

- 生成一致性核对报告 / 就绪报告 / 验收报告后、人工逐条审阅前，批量转成审阅视图。
- 审阅时先点「待决」只看欠人拍板的条目（`待确认/未确认/未验证/需要澄清` 等措辞或标签），逐个消解。
- 多份报告跨文档切换审阅：目录页按项目级/需求号分组，视图内左栏可直接切到目录内任意其他文档。
- md 更新后重跑刷新视图（幂等，派生物随时可重建）。

## Not For

- 不生成、不修改 md 本身——md 的产出契约属于各生成侧 Skill，本 Skill 只消费。
- 不发布、不上传：产物是本地审阅视图（file:// 打开）。
- 不做选项确认面板、角色切片（见 Limitations / Roadmap——这两项需要 md 侧结构化钩子）。
- 不扫描白名单之外的目录；找不到已知文档族时报错退出，扩 `FAMILIES` 须先与用户确认。

## Contents

- [`SKILL.md`](SKILL.md)：Skill 入口（含触发描述 frontmatter）——定位、核心原则、用法、文档族白名单、计数口径（条目/证据冲突/待决，`analyze()` 与模板 JS 同源）、模板维护与重验清单、边界。
- [`assets/build.mjs`](assets/build.mjs)：构建脚本，只用 node 内置模块。`node assets/build.mjs <项目根目录>`。
- [`assets/template.html`](assets/template.html)：视图模板（原生 JS，占位符注入），含三栏布局、待决/冲突/严重度筛选、搜索高亮、大纲滚动联动、深色模式。

## 形态说明

本 Skill 是「精简内核 + 可执行资产」形态：`SKILL.md` 常驻的只是定位、边界与计数口径，渲染逻辑全部在 `assets/` 的脚本与模板里，无需加载进上下文。脚本对任意传入的项目根目录工作，不绑定特定项目。

## Usage

### Claude Code

安装（符号链接到用户级 skills 目录，全局可用、跨项目）：

```bash
./scripts/install-skill.sh doc-review-views
```

对某项目生成/刷新视图：

```bash
node <skill目录>/assets/build.mjs <项目根目录>
# 产出 <项目根>/docs/review-views/：各视图 .html + index.html 目录页
```

### Codex 或其他工具

直接以 `SKILL.md` 为指令，用 agent 的脚本执行能力运行 `assets/build.mjs`；要求 node 内置模块可用（无第三方依赖）。

## Limitations

- **待决/冲突/严重度都是规则识别**（措辞与标签正则，清单见 SKILL.md 计数口径），不保证穷尽；规则变更须同步改 `analyze()` 与模板 JS，并按 SKILL.md 的最小验证集重验。
- 问题卡片的待决/冲突按**标题行**判定（与计数口径一致），卡片正文内的同类措辞不重复计。
- 条目登记只发生在严重度章节（高优先/中低/轻微）内：就绪基线、任务就绪报告这类无严重度章节的文档不进待决队列，只有「全部」pill。
- 从旧名 `doc-review-portal` 迁移：输出目录由 `docs/review-portal/` 改为 `docs/review-views/`，旧目录是派生物专区，可在项目内直接删除后重跑重建。
- 角色切片（设计/开发/产品各自视角）与选项确认面板暂不提供——md 侧尚无结构化载体。

## Roadmap

- **中期：md 侧加可抽取决策钩子**（需与各生成侧 Skill 协商产出契约）：如 `选项 A/B` 结构、`@role` 角色标记；HTML 侧据此升级为选项确认面板与角色切片。原则不变：钩子由生成侧 Skill 产出并留档，本 Skill 只消费。
- **短期已落地（2026-09-04）**：待决事项队列（视图 pill + 目录页计数）；证据默认折叠（问题卡片默认收起，现状已满足）。
