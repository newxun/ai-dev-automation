# Protocols：授权、安全、异常与报告

> 在访问外部设计源、启动浏览器、修改代码或生成报告前读取。

## 默认授权

用户调用本 Skill 即授权在当前任务范围内：

- 读取任务材料和声明的蓝湖/图片设计来源。
- 通过已配置的蓝湖 MCP 只读获取任务相关设计数据。
- 启动项目服务和浏览器，使用安全测试数据采集截图。
- 派发独立视觉诊断 Agent。
- 修改当前任务分支内与确定设计偏差直接相关的代码、样式和资源。
- 运行与修改范围匹配的自动化或浏览器功能测试。
- 生成设计证据、临时日志和 `docs/design-fidelity-repair/**` 报告，并清理本流程启动的进程。

默认授权不包括：绕过蓝湖或应用访问控制；读取/回显秘密；写生产或共享数据；支付、审批、发消息；
修改需求行为；部署；扩大到任务外重构。出现这些操作时先说明目标、影响、数据和回滚方式并请求确认。

## 设计与需求冲突

权威来源按维度使用：

- UI 呈现：设计稿 > 需求文档 > 有设计稿情况下的原型稿。
- 行为逻辑：需求文档 > 设计稿。

当两条规则无法同时满足时，不允许“折中设计”。报告以下最小决策包：

```markdown
- 冲突项：
- 需求行为证据：
- 设计呈现证据：
- 当前实现：
- 可选决策及各自影响：
```

即使用户此前说“不要问，直接修”，也只继续处理不冲突的确定问题；冲突项等待裁决。

## 异常与降级

| 情况 | 处理 |
| --- | --- |
| 蓝湖 MCP 不可用，但有可靠图片 | 继续图片视觉路径，标记结构化核对缺失 |
| 蓝湖链接失效或无权限 | 使用任务材料中的安全快照；没有则请求用户提供 |
| 无可比较的设计画面 | 停止，不以结构数据或代码检查替代最终画面对比 |
| 项目无法启动 | 记录启动证据并停止，不声称完成 |
| 页面需要未授权数据/副作用 | 只完成安全部分，其余请求授权或标记阻断 |
| 动态内容无法稳定 | 排除噪声区域；影响主要区域时标记无法可靠判断 |
| 视觉 Agent 不可用 | 若此前至少一个状态已完成独立诊断闭环，则为部分完成；从未形成闭环则无法完成 |
| 三轮后仍有偏差 | 停止并列出剩余问题，不继续消耗或扩大修改 |

不尝试绕过权限，不要求用户在对话中粘贴密码、Cookie 或 Token。

## 报告规则

使用 UTC、Windows 兼容时间戳 `YYYY-MM-DDTHH-mm-ssZ`：

`docs/design-fidelity-repair/tasks/<timestamp>-<task-id-or-slug>.md`

默认将被报告引用的设计画面、修复前后截图和独立诊断结果保存到：

`docs/design-fidelity-repair/evidence/<timestamp>-<task-id-or-slug>/`

若目标项目已有稳定的测试制品目录或仓库明确禁止提交图片，可改用项目约定位置，但报告必须记录
项目内可解析路径、保留方式和至少持续到 Scenario Acceptance 完成的保留期限。系统临时目录不能
作为报告的唯一证据路径；只清理未被报告引用的临时截图和日志。

同一次执行的 1–3 个修复轮次持续更新同一报告和 evidence 目录；新的会话或重新启动的一次独立执行
才创建新时间戳文件。使用 `report-template.md`，删除所有占位和空表格。大体积设计原始数据只记录
安全路径，不复制进报告正文。

报告中的代码 Commit、截图和测试证据必须对应同一轮代码。修改代码后，旧截图只能作为“修复前”
证据，不能支持最终结论。

## 最终回应

结果取值：

- **完成**：全部关键状态满足完成条件。
- **部分完成**：至少一个关键状态已经完成真实截图、诊断和修复复查，但另有状态或冲突项无法完成。
- **无法完成**：没有任何关键状态形成「设计画面 + 真实实现截图 + 诊断」的最小证据闭环。

```markdown
## 设计还原修复结果

- 结果：完成 / 部分完成 / 无法完成
- 已修复主要偏差：
- 待用户决策：
- 无法验证：
- 相关功能测试：
- 报告：`docs/design-fidelity-repair/tasks/<timestamp>-<task>.md`
```

不得使用「最终 UI 验收通过」「像素级一致」或没有证据范围的「完全还原」。
