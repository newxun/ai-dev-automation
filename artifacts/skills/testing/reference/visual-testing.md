# 条件化视觉测试

> 由 `SKILL.md` 引用。仅当存在视觉需求或视觉回归风险时才读入，不作为所有任务的固定步骤。

## 与浏览器功能测试的区别

- **浏览器功能测试**：验证页面加载、输入、点击、路由、权限、请求、数据状态和用户流程是否正确。
- **视觉测试**：验证布局、样式、遮挡、溢出、响应式或截图差异，不关心业务逻辑是否正确。

两者可以共用同一次页面访问采集的证据，但结论分开记录，不要把「页面能跑通」当作「视觉没有回归」。

## 何时启用

- 任务本身是视觉/样式/布局调整。
- 修改的组件或样式在多个页面复用，可能产生非预期的连带视觉变化。
- 用户或验收标准明确提出视觉回归风险。
- 响应式断点、多语言文案长度、暗色模式等已知易碎的视觉维度受影响。

不满足以上任一条件时跳过视觉测试，在报告中标注 `跳过` 并说明理由，不默认执行。

## 执行方式（最小化）

1. 只选择任务直接影响的页面/组件和关键断点（如桌面/移动两种，而不是遍历所有断点）。
2. 优先对比「修改前后」或「设计稿与实现」的关键状态截图，而不是无目标地浏览整个应用。
3. 只在必要时使用截图差异工具；没有工具时用人工描述差异点（位置、预期与实际）。
4. 发现的视觉问题记录：页面/组件、断点或状态、预期与实际截图或描述、是否阻断当前验收。

## 结果判定

- 关键状态视觉符合预期 → `通过`。
- 出现明显遮挡、错位、溢出、样式回归 → `失败`，标记是否属于验收阻断（通常是否阻断取决于是否影响可用性，而非任何像素级差异）。
- 缺少设计基准或无法判断是否符合预期 → `需人工确认`。
- 无法采集截图或无相关能力 → `无法执行`，说明缺口。
