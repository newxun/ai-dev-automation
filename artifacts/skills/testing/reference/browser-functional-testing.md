# 浏览器功能测试

> 由 `SKILL.md` 引用。仅当验收标准要求验证用户可见页面/流程，或其他自动化测试无法证明真实使用路径时才读入。

## 何时启用

出现以下条件之一应考虑浏览器功能测试：

- 用户可见页面发生变化。
- 登录、表单、导航或完整业务流程受影响。
- 需要验证前后端集成，接口测试无法覆盖真实交互链路。
- 验收标准明确包含交互行为。
- 其他自动化测试无法证明真实使用路径。

任务只涉及后端逻辑、CLI 或库时不启用；不因为项目「有 UI」就默认对每个任务执行浏览器测试。

## 验证等级

复用 development-readiness 环境验证的等级定义作为起点，聚焦到本次任务相关的页面和流程：

- `L1`：任务相关页面可访问、无阻断性加载错误。
- `L2`：功能流程所需的关键 UI 元素已渲染且可定位。
- `L3`：登录后/权限内的任务页面正常渲染。
- `L4`：任务相关的关键用户路径（输入、点击、路由、提交）可以安全触发并得到预期结果。

如果开发就绪阶段已经把环境和登录方式验证到 `L3`，本阶段只需在最终代码版本上复核该结论是否仍成立，不必重新走一遍认证确认流程；发现认证方式失效或页面行为变化时才重新确认。

## 认证

沿用开发就绪阶段确认过的认证方式（已有登录态 / 用户手动登录 / 已配置安全来源 / 不可取得）。认证方式发生变化或此前标记为「不可取得」时，只向用户确认一次，不重复要求粘贴密码、Cookie 或 Token。

## 执行方式

1. 从验收标准提取少量关键用户路径（通常 1–5 个），逐条列出触发步骤和预期结果。
2. 优先使用确定性脚本（例如浏览器自动化脚本）执行操作和断言，而不是自由探索。
3. 每条路径记录：访问 URL 与最终 URL、关键 DOM/渲染信号、`pageerror`、Console Error、失败请求、关键接口状态。
4. 在关键状态（成功结果、失败现场）采集截图或等价证据；正常路径不需要逐步截图。
5. 检测到宿主/子应用架构（微前端）时分别记录独立启动和宿主集成状态，不把该步骤套给普通项目。

截图只证明功能状态（例如弹窗确实出现、失败现场可复现），不用于评价位置、间距、颜色、视觉层级、
响应式观感、设计还原度或视觉回归。若元素存在但因遮挡而无法点击，记录“无法完成点击”的功能失败，
不扩展为截图式视觉审查。

## 结果判定

- 路径按预期完成且证据支持 → `通过`。
- 页面白屏、运行时报错、关键请求失败、结果与验收标准不符 → `失败`，标记是否属于验收阻断。
- 无法取得认证条件或必要环境 → `无法执行`，说明缺口和需要谁提供什么。
- 无浏览器能力时，相关结论降级为 `[未确认]`，不假装已经验证。
