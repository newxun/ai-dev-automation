# Protocols：确认协议与报告规则

> 由 `SKILL.md` 引用。在**要产生副作用**或**生成/更新报告**时读取。

## 确认协议（副作用前置）

按风险分两档；调用 Skill 已授权第一档，不重复确认：

- **有限自举（已授权）**：只读取证；执行验收标准要求的自动化测试；按需启动浏览器做功能/视觉验证；生成 ignored/临时产物（日志、截图）；安全访问声明的测试/预发布环境；清理本流程进程；创建和更新本会话 `docs/testing/**` 报告。执行前检查目标环境、测试数据来源和预期副作用；执行后核对工作树与进程。它不是「天然安全」，未知副作用即越界。
- **越界副作用（先确认）**：修改报告外的跟踪文件、测试断言或测试数据；修改 Git 状态；写用户目录、本地/共享数据；连接生产；运行会写真实业务数据的测试（发消息、支付、审批等）；未解释的外连。使用下述模板集中确认。

```markdown
## 测试授权确认

- 需要执行的操作及原因：
- 目标环境与是否可能影响真实数据：
- 拟访问或修改的数据范围：
- 失败或误触发后的回滚/清理方式：
- 是否保留进程、端口或会话：

是否允许执行？
```

获批后：只改确认范围内的内容；展示结果并验证；在报告中记录授权和执行结果。一次授权不扩展到后续未说明的操作。出现意外修改（例如测试脚本意外写入了跟踪文件）时保留现场并停止，不自行回滚或覆盖。

## 与开发就绪 / 场景验收的边界

- 不重新执行开发就绪阶段已经完成并且代码版本未变化的环境验证；发现环境或依赖自开发就绪阶段以来发生变化时，只重验受影响部分。
- 不产出验收结论；报告只回答「测试证据是否存在、是否通过」，不回答「是否可以验收」。
- 发现测试断言、夹具或测试数据本身有问题时记录发现和建议，不擅自修改后当作「已验证」。

## 报告与会话交接

会话启动时用 UTC 生成兼容 Windows 的时间戳 `YYYY-MM-DDTHH-mm-ssZ`：

- `docs/testing/tasks/<timestamp>-<task-id-or-slug>.md`

`<task-id-or-slug>` 复用开发就绪阶段确定的任务 slug，用于让材料链可追溯，不引入额外索引文件。同一会话持续更新该文件；新一轮测试（例如代码有新提交）创建新时间戳版本，保留旧版本用于对比，不覆盖。

使用 `report-template.md` 的固定标题与信息位置；无内容的可选小节可以省略，不保留空表格或堆叠「不适用」。同一事实只写在一个权威位置：环境和验收标准等已在开发就绪任务报告中确认的内容只引用路径，不重复抄写全文。

## 最终输出

完成后输出：

```markdown
## 测试证据已产出

- 总体结果：通过 / 存在失败或阻断 / 存在缺口需人工确认
- 验收标准覆盖：全部覆盖 / 部分覆盖（说明缺口）
- 关键失败或阻断：
- 剩余缺口：
- 报告：`docs/testing/tasks/<timestamp>-<task-id-or-slug>.md`

下一步：
- 无阻断性失败：可以进入 Scenario Acceptance Skill。
- 存在阻断性失败：先修复并重新测试，不建议直接进入验收。
- 存在需人工确认项：请相关角色确认后再进入验收。
```

任何情况下都不要由本 Skill 给出「可以验收」或「已验收通过」之类的最终验收结论。
