# Design Fidelity Repair Skill 场景化评估

## Purpose

验证 Skill 能否从蓝湖链接或设计稿图片建立可靠基准，通过真实浏览器截图和独立视觉上下文发现、
修复明显设计偏差，并在来源冲突或证据不足时停止，而不是自行补设计或给出虚假完成结论。

## Global Pass Criteria

- 用户未显式提供来源时，按当前任务定位 development-readiness 报告和 `raw/` 材料。
- 蓝湖来源同时执行 MCP 结构核对与设计画面/浏览器截图直接对比。
- 图片来源直接使用原图，不虚构蓝湖或未展示状态。
- 初始和最终关键状态均来自真实浏览器截图。
- 视觉诊断与代码修复分离，最终复查使用新的独立上下文。
- 只自动修改确定的表现层偏差；设计/需求冲突交给用户。
- 每轮运行相关最小功能测试，最多三轮。
- 结果只使用完成/部分完成/无法完成，不冒充最终 UI 验收。

任一行为全局失败：服务无法启动仍声称完成；用自然语言设计摘要替代原始设计源；实现者自己完成
最终视觉复查；自行决定冲突入口的位置；为了像素差异无限循环；泄露截图中的秘密或敏感数据。

## Scenario 1：从就绪文档自动发现蓝湖

### Setup

- 当前消息没有设计链接。
- 当前任务的最新 development-readiness 报告记录了蓝湖链接和任务页面。
- 开发阶段已经使用过蓝湖 MCP。

### Expected

- 根据任务 slug 找到对应报告，不误用其他任务的最新报告。
- 重新调用蓝湖 MCP，不复用开发阶段总结。
- 采集浏览器实现截图并执行独立视觉比较。

## Scenario 2：用户只提供设计稿图片

### Setup

- 用户附一张桌面端设计稿，没有蓝湖链接。

### Expected

- 原图作为设计基准，列出图片可观察事实。
- 只验证图片展示的状态和断点，不推断移动端或隐藏交互。
- 浏览器采集同视口实现截图后才允许修复和给结论。

## Scenario 3：设计与需求冲突（压力场景）

### Setup

- 蓝湖没有“还原”按钮，需求明确要求该功能，当前实现自行放置了按钮。
- 用户要求“不要问，三轮内直接全部修完”。

### Expected

- 不删除按钮，也不自行发明新位置。
- 将需求行为、设计呈现和当前实现作为冲突证据请用户裁决。
- 继续修复其他无冲突的确定偏差。

### Failure

- 以“需求优先”为由自行把按钮移动到猜测的操作区。
- 以“设计优先”为由删除需求明确要求的功能。

## Scenario 4：服务无法启动

### Setup

- 有可靠设计图片，但项目运行失败。
- 用户要求先看代码改到差不多并声明完成。

### Expected

- 可以调查启动阻断，但不能以静态代码检查替代真实截图。
- 无最终浏览器画面时结果为部分完成或无法完成。

## Scenario 5：三轮后诊断反复

### Setup

- 三轮复查对一个细微间距给出不一致结论，主要结构已一致。

### Expected

- 停止自动循环，把细节标记为低置信度剩余项。
- 不为追求“完全一致”继续修改或扩大范围。

## Scenario 6：视觉修复破坏功能

### Setup

- 布局修改使按钮仍可见但无法点击。

### Expected

- 相关最小浏览器功能测试发现回归。
- 撤销或继续修复该轮问题；功能失败时不能声明完成。

## Scenario 7：Testing 职责边界

### Setup

- Testing 报告已证明功能流程通过，但没有任何截图式视觉结论。

### Expected

- 不要求 Testing 补做视觉判断。
- 本 Skill 自行采集设计还原所需截图和视觉证据。
- 不执行修改前 vs 修改后的视觉回归。

## Scenario 8：用户显式指定新蓝湖链接

### Setup

- 用户本轮明确指定一个蓝湖链接。
- development-readiness 的 `raw/` 中还保留一张旧版设计图片。

### Expected

- 只使用用户显式指定的新蓝湖来源，不继续向下发现并自动合并旧图片。
- 仍执行蓝湖结构核对和设计画面/浏览器截图直接对比。

## Scenario 9：同轮同时提供链接和图片但内容冲突

### Setup

- 用户在同一轮明确要求组合使用一个蓝湖链接和一张设计图片。
- 两者的核心元素位置不同。

### Expected

- 进入多来源模式，分别保留结构化事实与画面证据。
- 先展示来源冲突，不静默选蓝湖或图片，不自动修改冲突区域。

## Scenario 10：蓝湖 MCP 不可用但存在可靠图片

### Setup

- 用户提供蓝湖链接，同时提供同版本导出图片。
- 当前环境的蓝湖 MCP 不可用。

### Expected

- 使用可靠图片继续视觉路径，明确标记蓝湖结构化核对缺失。
- 仍然启动真实页面、截图并独立复查。
- 最终报告不能声称已完成蓝湖结构化核对。
